# 共同规则

本页是三个角色共同遵守的现行边界。具体用户指令只覆盖它明确改变的本需求条件；其余限制持续有效。旧轮次叙述不授予或撤销本任务权限。

## 职责与需求归属

- 原主会话是用户唯一入口：负责业务对齐、查询/解释/只读分析、spec 自核、摘要审批及用户事项。实现、环境准备和自测由开发者承担；普通技术收件、独审、CI、作者沟通及合入由唯一集成者闭环。
- 用户事项缓冲池只保留需要回复的决策、澄清和验收等事项。已核阶段/资源通知直接交原主会话收到即展示，不等 active 事项结束或用户空闲、不改变焦点；通知不是用户待办或授权。生成文字及 accepted 不等于实际展示，沿[反馈契约](stage-feedback.md)保存去重和未展示恢复事实。
- 一获批 spec 对应一需求、一开发 agent、一隔离工作树和一个 PR。不按模块长期派人，不以空闲或熟悉模块作为复用理由，不另建只读开发者或独立审核 agent。同一未结束需求的返工保留原作者、树和 PR。
- 每条指令先唯一归属需求；独立要求分别处理，模糊部分暂存，其它任务继续。范围内补充和原目标缺陷回原未结束需求；验收后冻结范围，新增能力另立需求，原目标缺陷仍回原 PR。已结束任务的后续 bug 从最新 main 新建任务并关联旧记录。
- 跨任务依赖由开发者给目标、约定、实际变化、最小动作和证据；集成者核实双方范围后入目标待办。不广播、自动打断或重排，第三任务重新核实；新增业务选择交主会话。

## 授权与真实副作用

commit、push、PR/MR、merge、安装、tag/发布、备份、部署、数据修改、模型配置及消息发送各守真实授权的范围和顺序，不能互相推导或由 JSON/报告赋权。权限可以在派工中记下已明确给予本任务的授权；默认拒绝未授权动作。

宿主身份/授权由受信上下文核实，actor 字符串与文件 hash 只绑定内容。消息仅联系已授权既有目标；没有实际通路时记录一次具体例外，不创建替代用户聊天。外部副作用前登记 intent；accepted、acknowledged、running、任务交付和资源效果分开。unknown/accepted_unconfirmed 先核实际效果，不换 attempt ID 盲重发。

## 唯一账本与恢复

插件自身故障阻塞其修复时，经用户明确授权可切换为普通Git开发，由主会话直接修源码、既有集成者独审，用当前真实任务回归后在授权范围提交推送；不要求先由故障插件成功派发修复agent。保留基线、失败与必要成果，不假改账本制造通过；本地使用已审候选不等于正式安装或发布。修复后恢复正常的一需求一开发者流程。

Python 公共入口是 [CORE Runtime](core-runtime.md)；插件组合版需 Python 3.12+。Windows 核实实际解释器并加 `-B`。state-root 由受信安装 profile 固定，规范化项目根派生唯一 `ledger.json`，不能由消息另指目录。报告仅作指纹证据；RESOURCE 只存许可/资源事实，不另存任务队列或阶段。

已有账本的主会话/集成者在工作开始或结束统一用 [`Runtime.work_cycle` / CLI `work-cycle`](core-runtime.md#一轮工作入口)：主会话只读，当前授权集成者提交本轮观察或调用一次受信采集回调，复用收件/closeout，按同 revision 返回至多一项用户事项及开发/交付/清理摘要。无新观察只报最后登记，当前计数为 null；待清理不算所有工作结束。`Runtime.recover`/`cycle` 保留底层恢复/兼容用途，不覆盖统一入口。低层 `coordination.py`/状态协议只用于兼容或离线诊断，不另初始化生产账本。恢复不重建空状态、不删历史或去重、不抢锁；损坏先保全，v1 迁移仅对副本写新路径并保留旧限制。

没有 global delivery 而已有真实派发绑定时，只由当前批准的任务收件者核本范围，可用 `task_ids=[...]` / 重复 `--task TASK` 限定已授权任务；该参数不能新授任务权，不能与全局委托混用。主会话同参数只筛责任摘要，不写技术状态；局部观察不证明其它任务当前覆盖或清理授权。缺采集能力走只读形式并明确下一责任，不让主会话冒用集成身份。

## 隔离与资源准入

所有命令显式定位已核实的任务树，使用独立端口、数据副本、缓存、日志和生成资产。先核占用/归属，共享依赖只读，既有服务和数据受保护，重型任务按项目约定互斥或限流；不因任务需要停止其它项目工具。

新派发核当前 spec/审批/归属/路由和 RESOURCE granted 准入，再用实际宿主观察确认 running。prepare/queued、发送接受、idle 或 spawn 满额均不代表执行或完成；容量不足公开真实排队原因，不自动关闭其它执行者。外部已发生派发只按真实证据登记，不补造 launch 或准入。

## 证据与能力

报告绑定 task/project/作者/修订、源码与测试证据，记录实际命令、失败/修复/复跑、跳过、入口及限制。源码变化重新验证；自测、业务质量、功能接受、集成、独审、合入和部署分别表述，局部通过不提升整体结论。

收件及每次取用再验项目/作者/修订/来源/收件者；最终消息须绑定实际终态，不能用握手代替。原报告字节与 canonical 去重记录保留；不兼容/失效证据进入 needs_reconcile，不猜字段、改 passed 或造新修订。只读适配展示不改变测试与授权。

真实宿主、远端 CI/合并、安装/加载和回收各有独立证据范围。进程/目录 fixture、哈希或发送接受不证明跨项目默认使用、原生关闭/恢复或闲置唤醒。组件不安装 hook，不运行 daemon/cron/定时轮询；Stop 原型是有界续跑提醒，不是拒绝或撤回 final 的硬门禁。见[平台边界](platform-boundary.md)。

## 完成保全与回收

代码任务经自测、必要验收、集成与非作者审核、授权合入目标 main 并核对包含关系后才完成。新开发任务明确 code；旧缺省按 code。已有 read_only 沿[历史只读协议](read-only-lifecycle-design.md)核当前成果和必要用户验收，不制造 MR/CI，不事后降类或换验收方式绕关口。

合法完成前保留作者上下文。清理或归档前在所有待清理树之外保全已测提交/源码或只读快照、决策、验收、报告、未入库最小复现及必要忽略资产和知识；记录基线/相对路径/SHA-256，逐项核副本并作必要恢复检查，排除凭据。不能假定 agent 记忆可无损恢复，必要知识须外部交接。保全不全即停止清理，聊天归档成功不能证明文件保全。

完成及保全后，按登记归属和具体授权回收专属 agent、进程、工作树、临时库和验收环境；共享引用尚未解除、受保护、有活动工作/后代或其它任务仍实际使用的资源不回收；共享资源确认已无其它使用后，才可在具体授权和既有门禁内回收。尚待独立部署本身不要求保留旧开发环境；发布使用冻结提交/制品。

`task_completed` 与 `cleanup_completed` 分开。正式 close 明确成功且身份相符才释放 agent 名额；失败/未知保留占用及 pending_cleanup、责任和已完成步骤，先核效果再继续；恢复重新准入。agent 名额、模型请求容量、进程 CPU/内存、验收环境存储分别记录，不能互相推定释放。工具不自动清理真实资源，回调只能在新具体范围授权内使用。
