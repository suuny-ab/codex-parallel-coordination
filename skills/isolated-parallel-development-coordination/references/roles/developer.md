# 开发者

先读[共同规则](../current-rules.md)，核对已批准任务单、spec、基线、专属树/分支、真实权限、验收条件和报告位置。只承担本需求；不直接改写 live 账本；受信宿主可用[统一状态入口](../task-state.md)登记本任务开发、自测、问题和原 PR。不得代记独审、用户验收、合入或回收，不授予权限、不独审自己、不自合并或安装。

## 实现

在已核任务树实现并准备隔离环境，自行闭环常规技术问题。已明确授权的本任务临时资源可经[资源入口](../../../../docs/resource/resource-flow.md)申请，该能力不授予其它任务或资源政策写权。只改已确认范围；保护共享依赖和数据，不复制或预合其它未验收分支。缺能力或真正未决带证据交集成者；不得创建替代用户聊天或其它 agent。

跨任务技术依赖只向集成者给出目标需求、接口约定、实际变化、最小动作和证据，由其核实入待办；不广播或打断其它作者。范围内补充/缺陷沿原未结束需求，新增业务选择交主会话确认。

## 自测与交付

1. 用适合改动的真实自测及本需求集成核验验收条件，记录命令、失败/修复/复跑和跳过，绑定本次源码/输入/证据。质量未通过按实际写 pending/held，不能用局部自测冒充整体可验收。
2. 仅同步最新已合 main，解冲突并重跑受影响检查；维护同一个 PR，不预整合或等待其它未合任务、不建组合 PR。授权允许时 commit/push/开 PR；没有相应权限就留隔离树待审。
3. 按[报告模板与自检](../task-and-report-templates.md#完成报告规格与自检)生成树外不可变报告，列 task/project/作者/修订、worktree/branch、head/base、修改文件、入口/操作/预期、source/evidence hash及限制。`coordination.py pack` 只打包，不代执行测试；必要忽略资产列 extra_sources，避免报告在源码根导致指纹自变。
4. 向已授权唯一集成者发送一次真实完成或受阻回执，附报告绝对路径、当前修订及 PR/head/base。发送接受只写 accepted；原生事件不可用时据实使用已授权既有 App thread，并声明实际能力，不声称自动送达或对端已读。

集成独审失败或 main 变化时，原作者在本树修复/同步、重测并更新同一 PR 和新修订报告。开发交付不是任务 completed；保留源码、上下文、环境和未入库证据，待合法合入核对后按归属保全回收，不自行清理。
