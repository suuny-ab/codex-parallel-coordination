# RESOURCE component 1.1.2

Windows / Python 3.12+ / standard library. Copy `component/` unchanged into `codex_parallel_coordination/resources/`; import `Controller, ArtifactCleanup` from that package. The same `resources.py` also runs directly as CLI. No imports from CORE or yesterday's skill. Resource store schema is `coordination-resources/2`; snapshot schema is `coordination-resource-snapshot/1`. A v1 state is refused, never overwritten or silently migrated.

## Ownership and meaning

CORE is the only task, native-executor lease and task-cleanup authority. This store contains process requests, quota permits and registered artifact receipts only. A process `completed` means that managed process tree exited, not that the development task is complete. Slot `granted` is quota reservation, not evidence that a native agent started. App chat idle, report completed, `close_agent` acceptance, archive and release of all RAM are distinct facts.

Code-task closure follows development/self-test, acceptance, integration/review, merge into target main and verify, preserve minimal commit/decisions/acceptance/reproduction and knowledge handoff, then authorized cleanup of exclusive resources. Preserve code-task agent context before merge. Explicit `read_only` tasks (investigation/review/exploration without code changes) may complete through CORE's canonical delivery-verification entry; when user acceptance is required, it must pass first. RESOURCE does not infer completion from labels or report status and never fabricates main/MR/CI proof for read-only work. The earlier paused/waiting-acceptance early-close draft is withdrawn; see `before/WITHDRAWN_CLEANUP_DRAFT_R1.json`. A later bug is a new task from latest main linked to old records; a new capacity permit does not authorize resuming the old completed task agent. Deployment is a separate frozen-artifact task; pending deployment alone does not retain the old development environment.

## Instance policy

`Controller(absolute_state_path).initialize(absolute_policy_path)` creates one instance only. Every project on this machine must deliberately point to the same instance to share its permits. User/session-local Windows mutex serializes finite callers; an existing file writer lock, abandoned mutex or corrupt state is visible and never stolen. This is a cooperation boundary, not an OS sandbox against arbitrary same-account scripts.

Policy fields: `authority:{path,sha256}`, positive integer `max_parallel`, nonnegative byte `physical_reserve` and `commit_reserve`, `projects:{project_id:[absolute_roots...]}`, `executables:[absolute_files...]`, `exclusive_keys:[names...]`, `phase_resources:{operation_label:[required_exclusive_keys...]}`. Roots of different projects cannot overlap. `phase` is the static resource operation label, not a copy of CORE task stage. No 32GB or business-search constants are embedded. Optional positive `max_agent_slots` governs only plugin-owned reservations; actual host-wide native capacity remains unknown. Memory-provider injection is accepted only when policy `allow_test_memory_injection:true`; production default is actual Windows GetPerformanceInfo.

The bound authority file must contain `scope:"explicit_temporary_managed_resources",launch:true`. Optional `reclaim_idle:true`, `cleanup_task_processes:true`, `cleanup_artifacts:true` are separate scopes. A file records existing authorization; it does not grant authorization by itself. This delivery uses only newly created disposable fixtures, not real project/service permissions.

## Managed process API and CLI

- `submit(spec_path, run=False)` validates and enqueues, idempotent for the same request/contents. CLI `enqueue spec.json` does this.
- `submit(spec_path)` / CLI `submit spec.json` calls the finite foreground `pump()`: claim, create suspended process in new Job, durably register PID+creation time, resume, wait for process events, bind whole-tree exit evidence and release. Release drains the next FIFO request. Concurrent callers share one atomic quota. A single caller monitors one job at a time; parallel callers may run within configured quota.
- `claim()` is internal permit reservation (`starting` + `nonce`); it is not a running-process or agent-start acknowledgment. Do not claim then launch a separate shell outside this entry.
- `recover(request_id)` performs a one-shot actual Job/PID/exit-proof check. Live child, missing tree proof, reused identity or uncertain pre-registration launch keeps the permit. No timeout-based restart/free. A hash-changed or unbound exit file is not completion evidence.
- `idle(request_id,project,task,nonce,evidence_ref)` permits only an unprotected temporary auxiliary resource with explicit owner no-longer-needed proof. `reclaim(...)` requests termination of that exact owned Job and refuses wrong identity, protected usage or overlap with another permit. Termination requested is not whole-tree completion; the original monitor confirms exit.
- `task_cleanup(request_id,project,task,nonce,proof_ref,verifier)` is a separate trusted completed-task cleanup entry for explicitly opted-in dedicated task processes (`task_cleanup_allowed:true`, bound authority scope required). CORE verifies the kind-specific completion/ownership/permission before it can clear historical acceptance protection. Shared tools remain unsupported/protected. Returns termination requested, never task or cleanup completion before exit.

Process spec: nonempty `request_id,project_id,task_id,attempt_id,launch_identity,phase,purpose`; absolute allowed `cwd`; exact `argv` beginning with an allowed executable; positive `peak_bytes`; `exclusive_keys`; `resource_kind` in `temporary_auxiliary,compute,acceptance,regression,shared_tool`; `protection` in `none,running,waiting_user`; boolean `reclaim_allowed`. Only temporary auxiliary resources may use ordinary idle reclaim. Real computation/regression/shared tools are protected. Policy margins and reservations are conservative: available physical and commit headroom are re-read before admission and active peak budgets additionally reserved; measured shared working sets are never summed. No argv, engine budget, thread count, model or rules are rewritten.

CLI: `python resources.py --state ABS init POLICY`, `enqueue SPEC`, `submit SPEC`, `pump`, `recover ID`, `idle ID --project P --task T --nonce N --evidence FILE`, `reclaim ID --project P --task T --nonce N`, `show`, `snapshot [--project P]`, `model-capacity EVIDENCE`, `agent-capacity EVIDENCE`, `capacity-acquire SPEC`. `show` and `snapshot` do not persist changes. All other listed entries may persist resource records; process submit/pump/reclaim/recover can execute allowed process lifecycle actions. There is deliberately no JSON-only CLI bypass for trusted-verifier cleanup or capacity release.

## Native agent quota, no native lifecycle duplicate

`capacity_acquire(spec_path)` accepts exactly `request_id,project_id,task_id,attempt_id,launch_identity,resource_class:"agent_execution_slot"`. Returns a resource record with `status:"queued"|"granted"`, `permit_id`, sequence and spec. It never spawns/resumes/closes a native agent. CORE/REPOSITORY own the formal side-effect adapter and canonical generation/lease. The current host's close/resume path is not validated by this delivery; current four working actors are untouched.

`capacity_release(request_id,permit_id,receipt_ref,verifier)` requires a bound receipt with matching request/project/task/attempt/permit plus `outcome:"confirmed_closed"|"confirmed_not_started"`. The injected trusted `verifier(context,receipt)` must read the canonical CORE result; raw JSON or a callback that merely echoes it is not authority. Old boolean-only verifier is rejected. For confirmed_closed return all true: `verified,preservation_valid,no_active_work,no_active_descendants,no_release_dependencies,exclusive_task_resource,cleanup_authorized`, and `protected:false`, plus the current completion facts below. These transient facts are not stored as task stages. For confirmed_not_started, return `{verified:true,not_started:true}`; this frees an unused reservation, not agent context. Failed/unknown/accepted/idle/completed receipts cannot free quota. Duplicate release with the same receipt is idempotent. Returns `newly_granted` FIFO request IDs, not new agents, and `process_memory_or_acceptance_storage_released:false`.

Completion facts from CORE: explicit `task_kind:"code"` requires `task_completion_verified:true,task_completed_on_main:true,read_only_completion_verified:false`; explicit `task_kind:"read_only"` requires `task_completion_verified:true,task_completed_on_main:false,read_only_completion_verified:true`. Missing task_kind is the legacy code contract and still requires `task_completed_on_main:true`. Unknown kinds, inconsistent or missing new flags are refused. A read-only task's current revision/source evidence, delivery authorization/owner and applicable user acceptance must be checked by CORE's real verifier before returning these facts. Neither a kind label nor a completed boolean releases a quota or authorizes cleanup.

CORE must persist actual confirmed close/not-started results before release. Its guard/lease must prevent reuse while actual close is in flight. Resource verifier reads CORE only (no host I/O or nested writer lock); do not invert locks. Resume/re-dispatch requires fresh admission under the current task policy. Resource references cannot expand cleanup or lifecycle permissions.

`model_capacity(ref)` records explicit model-capacity facts without switching models or changing local permits. `agent_capacity(ref)` accepts `category:"agent_thread_limit",event_id,host_adapter`, deduplicates by bound event, and never fabricates running or releases memory. CPU/memory, model capacity, native quota, and acceptance storage are separate categories.

## Registered artifact cleanup

`ArtifactCleanup(controller, adapters={})` shares `state.cleanup_resources`; no other registry. Default adapter supports `temporary_file,temporary_directory,temporary_database,acceptance_environment`. Policy needs `cleanup_roots:{project:[absolute_roots...]}` plus authority `cleanup_artifacts:true`. The allowed root itself, state subtree, policy and authority are protected. Git roots/markers and links are refused by the default filesystem adapter; it cannot be used as a worktree-removal fallback.

`register(spec)` accepts `resource_id,project_id,task_id,attempt_id,kind,path,references:list[str],protected:bool`, optional provenance-only `metadata`. It records actual filesystem/adapter identity, not task stage. Duplicate same registration is idempotent; conflicting owner/path refused. `update_usage(id,project,task,attempt,references,protected)` updates explicit uses before any cleanup intent; shared references/protection block cleanup.

`cleanup(id,proof_ref,verifier,retry=False)` requires an external bound proof matching resource/project/task/attempt. The trusted verifier returns the same kind-specific canonical completion and common safety facts above; CORE's lifecycle guard must block new work/references throughout the operation. The resource records intent before invoking its trusted adapter. Only actual observed absence after a successful remove means `reclaimed`. Failure returns `pending_cleanup`; task_completed is never changed here. `observe(id)` is a mutating one-shot resource-receipt reconciliation, not a remove retry: an unknown operation later observed absent can become reclaimed. Unknown+still-present remains pending even with retry=True. Only explicit `failed_no_change` may be retried with fresh guards and `retry=True`. Directory partial failures are unknown; an atomic file unlink PermissionError with the exact original identity still present is failed_no_change.

Trusted custom handler protocol: `observe(spec)->{exists:bool,identity:dict|None,safe:bool,reason?:str}`, pure readonly; `remove(spec,expected_identity)->{status:"removed"|"failed_no_change"|"unknown",...}`. Register via code `adapters={"git_worktree":host_adapter}`; no dynamic imports or arbitrary command strings from JSON. A worktree adapter must bind exact repository/path/HEAD and refuse main checkout, dirty/locked/changed/shared/protected resources; only the integrator supplies and tests this capability. RESOURCE does not invoke Git or remove a real worktree in this delivery.

## Snapshot and limits

`snapshot(project_id=None)` returns schema/version/resource_revision/observed_at, scoped resource requests and capacity permits, actual system-memory sample, unique `(pid,creation_time)` process observations, private-commit sum only when measurement is complete, and registered cleanup receipts. Shared working sets are not summed; missing/changed source evidence is `needs_reconcile`, not precise ready/running claims. Storage bytes and full-machine resource ownership are not measured. This is no second task/agent ledger.

No background scheduler, timer, daemon or idle-main wakeup is installed. A managed exit can drain FIFO while its finite foreground monitor is alive. External memory changes without a reliable event are rechecked at the next explicit entry. Ordinary Windows Job IOCP notifications are not guaranteed delivery; absence is not proof of exit. Recovery retains uncertain ownership rather than restarting. No global hard memory enforcement of processes bypassing the plugin is claimed. Actual native agent close/resume, full host integration and install/upgrade acceptance are separate from these component fixtures.

Long evidence paths: shared JSON/hash/atomic-replace I/O uses Windows extended absolute aliases when the path reaches 260 characters. Artifact metadata retains the original normalized absolute path and SHA256; changed evidence still fails its old binding. This addresses the real deep-path recovery-proof failure without changing system settings or moving tests to a shorter root. It is not a claim that every arbitrary process, state lock, filesystem adapter or Windows path form supports unlimited lengths.

Cooperating Windows JSON/hash readers request read access with shared read/write/delete. Existing destinations use ReplaceFileW with no ignore-ACL flags; initial creation still uses os.replace. Actual held-reader tests show the previous snapshot remains readable while the new path is replaced. Handles close with the stream; no permissions/ACL are expanded, writer locks are not bypassed, and restrictive external handles still refuse replacement. Documented partial replacement errors 1176/1177 retain the fsynced new temporary snapshot for explicit recovery. No retry or truncate-write fallback runs. See [CreateFileW sharing semantics](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) and [ReplaceFileW failure semantics](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew).
