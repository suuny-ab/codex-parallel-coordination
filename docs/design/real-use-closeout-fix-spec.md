# 本地真实使用的任务事实衔接修复（待派工审批）

## 为什么做
PR13/PR14 已独立审核并合入 main35ee69d，正式 CLI 已安装插件。安装源码对原唯一账本试读，发现独立审核、CLI 作者和实际合并事实未能完整进入规范状态。ROOT 的 describe 已能记真实说明，但不能替代质量、执行归属和完结事件。证据见 installation-main-r1/REAL_USE_FINDINGS.json；不得把这一现状写成完整闭环已通过。

## 一个需求、一个交付
一份 spec、一个新开发agent、一个独立工作树/分支、一个新PR。三个缺口属于同一条任务事实流，一起修，避免拆成多个并行修改同一状态协议的任务。PR13/14保持已合并事实，不重新打开。以派工时最新main为基线。集成agent技术验收和交付，不要求用户手工验内部状态代码。本文不授权在摘要获批前派工。

## 范围
1. 独立审核可以通过受控公开入口附加为同一任务、同一精确源码的证据。保留作者不可变报告，不把报告内的pending永久当成后续独审未发生；不允许作者自批、跨任务套报告或接受已过期的源码质量证据。
2. 正确区分纯技术任务的自动验收、需要用户操作验收的任务，以及用户的合并授权。当前两项已由用户明确批准合并，准确保存这项授权及实际Git结果；不伪造人工验收accepted、CI通过或客户签字，不以自动验收绕过需要用户验收的任务。实际合入目标main且核验后，允许登记真实完结；后续无关main变更不能推翻已证实的历史完结事实。未合入者仍不得标为完成。
3. 对真实Codex exec执行者提供有边界的事实登记和收件方式，保留CLI thread、进程和JSONL终态及原始派工/工作树/分支/作者报告/Git产物的对应关系，明确区别于native来源。不得补造native agent ID、spawn回调、资源准入或自动事件；进程结束不等于代码任务完成。
4. 通过已有唯一账本和公开入口串起审核、合并及完结；不新增旁路状态库、不直接改账本。失败/未知执行结果保留原因和责任人，保全不完整时不清理。仅允许已确认专属资源的按序回收，保护主工作区、集成agent及其它活跃任务。

## 验证与交付
用已冻结的真实A/B报告、审核、合并和作者终态，在隔离账本副本先复现再修复，并覆盖越权、错任务、错源码、重复回执及真实/未知副作用。源码绑定通过后，由合法角色经公开入口在原唯一账本对账，不伪造历史事实。作者自测与集成独立回归分别报告。
提交、推送并提一个PR，集成复核通过后按批准交付门禁合并；更新本机已安装副本，绑定实测main版本，验证状态与实际任务一致。更新前备份本插件；保留其它插件、配置和原账本。桌面加载需真实客户端证据；需要重载时只提出一个清楚的用户操作，不能以复制目录/CLI调用声称桌面已加载。

## 不做
自动唤醒、定时查询、原生并发额度修复、其它项目迁移、公开发布或tag、取消已确认的人类业务决策关口，以及扩大任务路由/资源回收业务规则。
