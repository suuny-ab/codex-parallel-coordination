# 任务结束与资源回收

2026-10-31 的早期草案曾允许“暂停/等待验收任务可释放不运行的 agent 名额”。用户随后明确撤回这项默认提前回收策略。历史事件保留；本版不得依旧草案执行。

代码任务的验收与测试在合并前完成，合入目标 main 并核对后，才代表任务结束。无代码改动的排查、审阅、探索任务由交付者核验当前成果后结束；明确要求用户验收的仍须等用户通过。达到各自合法结束点前保留执行者上下文，不能假定关闭后可无损恢复其记忆。

登记时明确 `task_kind=code|read_only`，只读任务再明确 `acceptance_type=delivery_verified|user_required`；旧记录缺少类型时仍按代码任务处理。确认时冻结输入源快照，只读完成入口核验当前修订、任务归属、确认依据、授权、源未变化及外部成果。只读任务不伪造 MR/CI，也不借旧任务 owner 或直接写完成状态绕过 canonical 入口。实现中保留代码任务原来的合入门禁，禁止事后降类。

结束后先核对：

1. 代码任务确认已测试代码合入指定目标 main，记录仓库、目标引用及包含关系证据；只读任务确认当前成果经交付者核验，并已取得原要求中的用户验收。
2. 已测提交或只读输入快照可追溯，必要报告、未入库的最小复现证据与知识交接已外部保全，仍保留责任和验收结论；不要求长期保留整套旧工作树。
3. 没有运行工作、活动后代或其它任务仍实际依赖这些资源；等待独立部署本身不是保留旧开发环境的理由。
4. 资源明确属于本任务，且不共享、不受保护、不被其它任务使用。

2026-10-31 用户先明确同意：开发自测 → 验收 → 集成回归审核 → 合入 main 并核对 → 保全必要记录 → 回收专属资源并归档；随后确认上述无代码任务的独立结束点。此增量保留原代码流程，未撤销已撤回草案的记录。本轮仅对本插件登记的隔离临时测试资源执行回收实验；未授权任意真实历史资源批量清理，真实 JLJ 工作树、环境、数据和当前四名执行者继续保护。

达到对应结束点并保全后，按登记归属回收专属 agent 执行名额、进程、工作树、临时库及验收环境；共享资源先确认其它任务不再使用，受保护资源不能直接回收。归档只保留提交号或输入快照、关键决策、验收结论和最小复现证据。必要知识须写入交接，不能把 agent 记忆当作可无损恢复的持久记录。

`task_completed` 与 `cleanup_completed` 分离：前者绑定对应合法结束证明，后者逐项绑定实际回收结果。任一清理失败或结果未知保留 `pending_cleanup`，任务与责任不丢失，成功步骤不重复执行，未知先只读核对再决定后续动作。后续 bug 从最新 main 新建任务并关联旧记录，不长期挂旧 agent；部署另建任务，绑定冻结提交和制品，不依赖旧开发环境。

正式 close 返回明确成功且身份相符后，才记录 agent 名额释放；失败、超时、未知结果均保留占用，先只读核对，不盲重发。恢复需重新准入。名额释放、模型容量、进程内存、验收环境存储分别记录，不能推断彼此已经释放。
