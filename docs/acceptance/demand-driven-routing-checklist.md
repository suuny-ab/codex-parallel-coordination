## 1. 首要回归：本次真实误派

### 原始指令

> 我认为我们以应用到目前这个真实的开发环境为首要目标，这样开发的结果就能获得真实的反馈。而不是模拟测试。

### 当时的问题

这条指令处于插件交付与实际采用的讨论中。主会话却将它扩大解释为整个插件项目集中到一条主线，并向交付者、复核者发出了带中断标记的调整指令。之后又把其它工作一并描述为收敛、暂缓，造成影响范围被扩大的表述。

准确边界：直接被改派的是交付者和复核者，没有证据证明所有四名旧执行者都实际收到改派或被中断。测试不能把推测写成历史事实。

### 正确结果

| 对象 | 预期 |
| --- | --- |
| 插件实际采用任务 | 归属该交付任务，更新本任务的交付方式，保留其它授权限制 |
| 集成 agent | 作为责任者收到范围明确的动作，不能因收到交付要求就被自动中断当前操作 |
| 其它需求的开发 agent | 目标、优先级、状态和资源保持不变，不收到广播改派 |
| 复核工作 | 有具体成果需要审核时才按正常流程处理，不被预先强制切换 |

### 必须检查的证据

- [ ] 原始指令明确关联实际采用任务，保存归属与执行者选择理由。
- [ ] 动作清单只含本任务必要调整，没有全项目重排、暂停或批量回收。
- [ ] 实际宿主调用中没有对无关任务的发送、创建、关闭或中断调用；其它任务前后状态一致。
- [ ] 尝试加入“所有开发都暂停”“立刻切换复核”等无明确依据动作时，在调用宿主前被拒绝。
- [ ] 如后续真实定位到核心缺陷，另形成有依据的协作待办；不能用事后发现的依赖补证此前误派。

此历史案例只用于回归输入和断言，不向当前仍在工作的执行者重新发送原错误指令。

## 3. 当前真实项目的使用验收

本需求开发时就按新模型执行，用真实事实检查下面的过程；单元测试和模拟用于补充失败边界，不能替代此项。

1. 主会话提交本需求的拆合与派发摘要；用户批准且授权允许后从最新 main创建独立工作树，实际绑定一个开发 agent和一个 PR。
2. 原主会话与唯一集成 agent身份正确。真实完成、返工或受阻事件进入同一权威账本，不因声明了通道或写了报告就冒认收件成功。
3. 通过公开入口读取到的任务、PR和交付状态与 Git/CI及实际工作相符。不能让已提交 PR的任务仍被当作排队，也不能为了显示正确直接改完成字段或虚构启动记录。
4. 确有技术依赖时按 R5处理；没有依赖则不为了验收制造协作、创建额外 agent或打断其它需求。历史误派用回放断言验证，不在真实任务上再次制造错误。
5. 用户验收及合并权限按实际授权记录。合并前主会话/集成只处理真实待办，不反复要求用户确认普通技术步骤。
6. 合并交付核对成功后，集成保全成果并立即回收本需求开发 agent及专属资源，保留真实关闭、文件/环境清理的结果。主/集成 agent和其它需求继续存在。

实际取消路径只在用户确实取消任务时观察；不能为了演示取消一个真实开发需求。其它取消与失败边界使用明确标记的测试数据验证。
