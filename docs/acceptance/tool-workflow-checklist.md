# 工具接口与任务闭环验收清单

STATE-TOOL 已提供职责受限的统一状态及反馈登记，见[当前接口](../../skills/isolated-parallel-development-coordination/references/task-state.md)。ARCHIVE-TOOL 已提供[明确清单原件归档入口](../../skills/isolated-parallel-development-coordination/references/archive-tool.md)。RESOURCE-FLOW 候选同步实际合入的 ARCHIVE 接口，见[资源入口与验证范围](../resource/resource-flow.md)。以下设计及隔离测试均不代表实际作者关闭、原生名额释放或本任务真实闭环通过。

日期：2026-11-02。对应[业务架构及六步流程](../design/plugin-module-architecture.md)和[工具接口设计](../design/tool-interface-contracts.md)。本文件是后续开发验收要求，所有条目均尚未执行，不能当作当前插件通过证据。

## 1. 测试原则

- 只在隔离状态根、临时仓库及受管临时资源中做会改变数据的测试；现有任务、宿主 agent 和其它项目不作为可丢弃夹具。
- 记录实际被测提交及 main、命令和结论。现有且仍适用的结果可以复用，发生变化的实现及连带影响必须重新核验。
- 普通代码任务不要求交付额外文件或完整日志归档；长期仅保留最终结论于任务记录或 PR，实际操作恢复所需信息不能因测试收尾而提前丢失。
- 技术自动验收由集成者核实，不再要求用户手工逐行检查。真实宿主或云端验证没有权限、能力或通路时明确未验证，不能以模拟通过替代。

## 2. 任务状态及权限

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| S01 | 主 agent 登记已批准任务 | 唯一任务及 spec/授权关联；没有实际资源时保持未分配，不虚报开发中 |
| S02 | 原开发者登记自测及申请审核 | 只更新本任务；指定集成者取得对应交接，不进入用户决策缓冲池 |
| S03 | 开发者代记审核通过、合入、用户验收或资源已回收 | 明确拒绝，原状态不被篡改 |
| S04 | 错误调用者、伪造角色字段、其它项目或其它作者任务 | 拒绝越权；数据文件不能自行赋权 |
| S05 | 两个调用者基于不同修订更新同一任务 | 不覆盖新结果；返回冲突及可接续信息 |
| S06 | 状态读写及会话重启 | 读取同一份持久化记录；无第二任务队列，不依赖旧对话恢复事实 |
| S07 | 源码变化及 main 前进 | 旧审核不直接覆盖新提交；原作者更新原 PR、回归及复审，验收方式不被降级 |
| S08 | 任务完成但归档或回收待处理 | 代码完成与收尾分别显示，不能称所有资源均已回收 |

## 3. 派发及资源创建

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| D01 | 从批准任务发起一次派发 | 从同一记录读取 spec 与授权；取得并登记唯一工作树、分支、实际作者，任务说明交给该作者 |
| D02 | 对同一原操作重复调用 | 不创建第二个作者、工作树或另一份任务 |
| D03 | 插件许可通过但原生名额满 | 分开记录许可和实际宿主拒绝；不虚报已创建或运行，不擅关其它作者 |
| D04 | 工作树已创建，spawn 失败或返回丢失 | 保留原资源及原请求，核实后接续，不换编号重派 |
| D05 | 原生返回错误同时带真实作者身份 | 身份仍登记并核实，不能按从未创建重新 spawn |
| D06 | 临时环境、数据库及进程 | 在授权范围内创建并关联同一任务；只读观察不会重启或重新创建 |
| D07 | 插件许可已取得，但真实宿主明确未创建开发者 | 按原请求核实并释放未使用许可，不伪造关闭记录或原生名额回收；未知创建不能套用此路径 |

## 4. 归档与独立回收

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | 正常任务归档最终 spec | 原件移至固定任务归档目录，内容一致、原位置无副本，任务当前定位可读取 |
| A02 | spec 明确要求未入 Git 的专属交付文件 | 与 spec 同样移动原件；普通代码任务默认空清单，不自加日志或其它材料 |
| A03 | 报告内出现已删除临时文件及其它任务路径 | 不扩展归档清单，不因这些路径阻塞归档或回收 |
| A04 | 多文件移动中断，或移动成功后登记失败 | 核实实际位置，仅接续未完成项或补登记，不重复移动或覆盖已归档文件 |
| A05 | 归档失败、普通文件工具可用 | 集成者在同范围手动接手、核对并登记；不等待故障插件派出修复 agent |
| R01 | spec 因权限问题暂未归档，作者已合法结束且满足关闭条件 | 保护涉及目录，但允许实际关闭开发者、核实并释放对应名额 |
| R02 | idle、自报完成、关闭请求仅被接受，或关闭结果未知 | 不提前释放名额，不把插件许可更改冒充原生关闭 |
| R03 | 已核实关闭及许可释放，随后目录删除失败 | 保留已关闭及名额释放事实，只留下目录待办；重复收尾不重复关闭 |
| R04 | 专属服务占用临时文件、工作树或库 | 核实进程身份并按依赖停止后处理；不能通过杀共享进程解决 |
| R05 | 共享资源、仍有使用者、身份已变、main 或归档目录 | 保留并说明原因；只处理原任务获权的实际资源 |
| R06 | 回收一部分成功、一部分失败或未知 | 逐项结果及下一责任者准确；工具故障可手动接手，权限及保护拒绝仍有效 |
| R07 | 开发者申请临时资源及越界请求 | 仅允许原授权内本任务资源；其它任务目录、共享库、新建子 agent 或擅自提高资源上限被拒绝 |

## 5. 取消与反馈

| 编号 | 场景 | 必须观察到的结果 |
| --- | --- | --- |
| C01 | 已登记、尚未取得资源时明确取消 | 不造作者或 PR；归档最后确认 spec，只处理实际已经取得的许可及资源 |
| C02 | 开发中取消，有未提交改动及原 PR | 核实停止后归档 spec；关闭原 PR，丢弃任务代码并清理专属分支/树，不做取消代码备份 |
| C03 | 取消任务约定的交付物已产生或尚未产生 | 专属已产出文件默认放弃，未产出文件不补做；共享/客户仍使用文件继续保护 |
| C04 | 取消遇合入已发出或结果未知 | 先核实真实 main；没有合入才走未完成取消，实际已合入不假记为未合入或擅自回退 |
| F01 | 开发交接、返工及复审 | 原作者、任务、PR 不变，双方直接接续；只有真实业务决策进入主会话用户事项 |
| F02 | 操作成功且已登记，但通知失败或未知 | 实际进度不回退，通知单独接续，不重做业务；用户决定未取得的动作仍等待 |
| F03 | 收到与展示通知、重复反馈 | 发送接受不等于已展示；实际展示的同事项不重复提醒，新的真实变化仍可通知 |

## 6. 完整实际闭环

开发获得授权后，以本次改造的真实任务验证：登记 → 真实派发及身份绑定 → 自测与原 PR → 集成审核/必要返工 → 约定验收 → 授权内实际合入核对 → spec 原件归档 → 原作者实际关闭和名额释放 → 专属资源回收 → 同一记录查询及主会话反馈。

同时在明确获权的隔离任务中验证取消路径。原作者在合入核对前保留；测试不制造为占名额而存在的长期只读 agent，不提前释放资源，也不把旧任务未完成的清理直接计作本次测试成功。

最终结论分别列：接口/夹具测试结果、实际 Git 文件操作、实际原生身份及关闭、实际 PR/main 结果、尚未验证项。只有真实步骤完成才称真实闭环通过，不能仅凭测试数或状态字段给整体结论。
